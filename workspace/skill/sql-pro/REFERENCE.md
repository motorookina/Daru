# SQL Pro - 技术参考

## 此技能的功能

SQL Pro 分析数据库 Schema、优化查询性能、设计高效的数据库结构，并实现确保跨多数据库平台可扩展性与数据完整性的数据管理方案。

### Schema 分析
- 审查数据库设计与规范化
- 分析索引使用情况与有效性
- 识别查询模式与瓶颈
- 评估数据分布与增长
- 评估约束设计与引用完整性
- 检查统计信息准确性与维护

### 实施阶段
- 设计基于集合的操作，避免逐行处理
- 优化子查询与 CTE 的性能
- 应用合适的连接策略与算法
- 实施正确的索引策略
- 利用平台特性与优化手段
- 记录查询意图与逻辑

### 性能验证
- 分析执行计划并识别瓶颈
- 确认索引使用与扫描减少
- 消除表扫描与键查找
- 更新统计信息以获得准确的执行计划
- 消除死锁与阻塞
- 用生产数据量测试可扩展性

## 最佳实践

### 查询开发
- 从理解数据模型与关系开始
- 编写可读的 CTE，将复杂查询拆分为逻辑步骤
- 尽早应用过滤条件以减少行数
- 使用 EXISTS 而非 COUNT(*) 做存在性判断
- 避免 SELECT *，只指定所需列
- 使用 OFFSET-FETCH 或 LIMIT-OFFSET 实现分页
- 用 IS NULL/IS NOT NULL 显式处理 NULL
- 用生产数据量测试查询

### 索引策略
- 在 WHERE、JOIN、ORDER BY 使用的列上创建索引
- 使用覆盖索引消除键查找
- 考虑对选择性查询使用过滤/部分索引
- 按选择性排列复合索引列顺序
- 监控索引使用情况并删除无用索引
- 定期重建/重组碎片化索引
- 在读写性能间权衡索引选择

### 性能调优
- 优化前始终分析执行计划
- 更新统计信息以获得准确的查询计划
- 使用参数化查询以便计划复用
- 对大表考虑分区
- 查询提示仅作为最后手段
- 监控等待统计以识别瓶颈
- 为并发设置合适的隔离级别
- 使用合适的数据类型以最小化存储并提升性能

### 数据库设计
- 规范化以减少数据冗余（通常为 3NF）
- 读密集型负载下适度反规范化以提升性能
- 为列使用合适的数据类型
- 定义约束以保证数据完整性
- 从一开始就规划增长与可扩展性
- 记录 Schema 决策与业务规则
- 实施恰当的命名规范
- 为查询模式设计，而非仅为数据存储

- **data-engineer**：支持 ETL/ELT 管道优化与数据转换
- **python-developer**：协助 ORM 查询优化与 SQLAlchemy 模式
- **java-architect**：协作 JPA/Hibernate 查询优化与 JPQL
- **performance-engineer**：处理数据库性能调优与监控
- **devops-engineer**：协助数据库部署、迁移与 CI/CD
- **data-scientist**：帮助优化分析查询与数据提取
